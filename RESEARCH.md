# Watch Together provider research

Reviewed 9 October 2026 against official provider documentation and terms. ARNS embeds providers’ own players; it does not fetch, resolve, download, store, or rebroadcast video.

| Provider | Findings | Decision |
|---|---|---|
| YouTube | The official IFrame Player API supports play, pause, seek, and player state events. Developer policies require preserving player functionality and ads; overlays must not conflict with the player. Videos with embedding disabled must remain unavailable. [IFrame Player API](https://developers.google.com/youtube/iframe_api_reference), [Developer Policies Guide](https://developers.google.com/youtube/terms/developer-policies-guide) | Added. Use only videos whose uploader permits embedding. |
| Vimeo | The official Player SDK controls embedded players and exposes playback events. Vimeo’s terms permit embedding its player on third-party sites when the viewer has permission; owners can disable embedding or restrict it to domains, and ARNS must respect those settings. [Player SDK](https://developer.vimeo.com/player/sdk), [Terms of Service](https://vimeo.com/legal), [Embed privacy settings](https://help.vimeo.com/hc/en-us/articles/12426259908881-How-to-embed-my-video) | Added. The provider remains responsible for its own embed restrictions. |
| Twitch | Twitch’s official embed supports live streams and VODs. Its player API supports playback control; seeking is not available for live streams. Embeds require HTTPS, a matching `parent` domain, approved player elements, and minimum dimensions; Twitch may revoke noncompliant embeds. [Embedding Twitch](https://dev.twitch.tv/docs/embed/), [Video and Clips API](https://dev.twitch.tv/docs/embed/video-and-clips/) | Added for channels and VODs. Use External sync if a Twitch player is unavailable or too narrow on a device. |
| Dailymotion | The official Web SDK exposes play, pause, seek, state, and playback events. Current terms permit viewing/sharing through its embeddable player when the uploader has the necessary rights, prohibit modifying or blocking player functionality, and require authorization for the destination app. Its SDK requires a Player ID configured in Dailymotion Studio. [Web SDK methods](https://developers.dailymotion.com/reference/web-sdk-player-methods), [Web SDK setup](https://developers.dailymotion.com/v0/docs/getting-started-with-the-web-sdk), [Terms of Use](https://legal.dailymotion.com/en/terms-of-use/) | Added, with a public `VITE_DAILYMOTION_PLAYER_ID` build value. Keep Dailymotion’s player and monetization behavior intact. |
| Wistia | Its official Player API supports control, but its terms prohibit making the service available for third parties through a service-bureau arrangement without prior written consent. That does not clearly authorize ARNS’s multiuser rooms. [Player Embed API](https://docs.wistia.com/docs/player-embed-api), [Terms](https://wistia.com/terms) | Not added. Obtain written permission before considering a room adapter. |
| Direct file / HLS | hls.js is a client playback library, not a hosting or rights grant. It can load a host-supplied HTTPS URL in the browser. The room requires the host to confirm they have rights; providers’ access controls and browser CORS still apply. [hls.js](https://github.com/video-dev/hls.js) | Added with a rights checkbox and visible warning. No resolver or source discovery. |
| External sync | No video is embedded in ARNS. Each participant opens a stream they can legally access; ARNS shares only the room clock, messages, and reactions. | Added. This is the supported path for services that do not authorize third-party playback control or rebroadcast. |

This is an implementation review, not legal advice or a guarantee that any particular upload is authorized. Provider terms and SDKs can change; check the linked official pages before a public launch.
